# Le problème avec React (pourquoi VueJS est plus simple)

1) **Idée principale** : L'auteur analyse pourquoi le framework React suscite autant de critiques en raison de sa syntaxe JSX (considérée comme un DSL hybride entre JS, HTML et CSS) et compare ses avantages et inconvénients avec Vue, React Native et des bibliothèques en ligne de commande.

2) **Outils, sites ou dépôts GitHub cités** :
- **React** : Non précisé (gratuit/payant), framework frontend.
- **Vue / Vue.js** : Non précisé (gratuit/payant), framework frontend alternatif.
- **React Native** : Non précisé (gratuit/payant), écosystème pour applications mobiles cross-platform avec React.
- **React Three Fiber** : Non précisé (gratuit/payant), outil pour afficher des éléments 3D en React.
- **Ink** : Dépôt GitHub / Outil open source (gratuit), permet de créer des applications de ligne de commande (CLI apps) avec React (plus de 108 contributeurs, utilisé par 81 000 projets).
- **Raycast** : Non précisé (gratuit/payant), outil/extension pour optimiser l'utilisation de React et générer des QR codes, etc.
- **shadcn/ui** : Non précisé (gratuit/payant), bibliothèque de composants UI.
- **mlv.sh/react** : Site / Lien de formation (non précisé, gratuit/payant), cours React mentionné par l'auteur.

3) **Astuces concrètes et réutilisables** :
- Utiliser **React Three Fiber** pour intégrer facilement des rendus 3D interactifs dans une application React.
- Utiliser **Ink** pour développer des interfaces en ligne de commande (CLI) en profitant des composants React.
- S'appuyer sur **React Native** pour partager la même logique et la même écriture de composants entre le web et les applications mobiles (iOS, Android, macOS, Windows).
- Maîtriser le modèle mental de React (« UI = f(state) ») pour structurer proprement le rendu des interfaces.
