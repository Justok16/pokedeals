# SuperPowers rend Claude Code plus lent (et BMAD est encore pire)

Vidéo : https://youtu.be/R6P669gbROs · durée 19:11 · résumé Gemini (gemini-3.5-flash-lite) du 2026-10-26
(connaissances générales, non vérifiées : toute règle fiscale ou chiffre est à contrôler à la source officielle)

Voici le résumé de la vidéo, structuré pour quelqu'un qui cherche à gagner de l'argent légalement avec l'IA et Claude Code :

1. **Idée principale** : 
L'auteur affirme que les outils/frameworks complexes comme *Superpowers* ou *BMAD* sont contre-productifs, scammeurs, ralentissent le travail et augmentent les coûts, car ils surchargent le contexte des grands modèles de langage (LLM) avec des instructions et des fichiers Markdown superflus. Selon lui, il faut privilégier la simplicité : un prompt clair et direct, inspiré par les compétences (skills) minimalistes de créateurs comme Matt Pocock, sans méthodologies rigides à 8 étapes.

2. **Outils, sites et dépôts GitHub cités** :
* **Claude Code** : Outil d'IA (non précisé si payant ou gratuit, mais l'auteur mentionne l'utiliser pour un coût de 17 000 $ sur les 30 derniers jours). Sert à coder et automatiser des projets avec l'IA.
* **Superpowers** (Dépôt GitHub : `obra/superpowers`) : Framework/plugin gratuit. Présenté comme un ensemble de skills (15 au total) basés sur des dossiers Markdown pour structurer le développement (brainstorming, TDD, etc.). L'auteur le qualifie d'outil inutile et lent.
* **BMAD / BMAD-METHOD** (Dépôt GitHub : `bmad-code-org/BMAD-METHOD`) : Framework/plugin gratuit. Présenté comme une méthode agile avec plus de 31 skills et 274 fichiers Markdown (environ 350 pages de consignes). L'auteur le qualifie de « pur bullshit marketing ».
* **GitHub** : Site gratuit, utilisé pour héberger les dépôts de code et de skills.
* **Chroma** : Source d'une étude (« Context Rot », juillet 2025) sur 18 modèles, citée pour montrer que plus un modèle lit d'informations de règles, moins il est efficace (fiabilité en baisse).
* **Graphite** : Outil/entreprise cité pour ses statistiques sur la taille médiane des *pull requests* (47 lignes).
* **Skills de Matt Pocock** (Dépôt GitHub : `mattpocock/skills`) : Ensemble de skills minimalistes et ciblés (comme `grill-me`), recommandés par l'auteur pour leur simplicité et leur efficacité par rapport à Superpowers ou BMAD.

3. **Astuces concrètes et réutilisables** :
* **Éviter les frameworks lourds** : Ne pas utiliser de frameworks complexes (comme Superpowers ou BMAD) qui injectent des milliers de lignes de consignes à chaque tour de conversation, ce qui sature le contexte de l'IA (« context rot ») et réduit sa fiabilité.
* **Privilégier les prompts directs et simples** : Pour 90 % des tâches courantes (corriger un bug, changer un texte, ajouter un champ), un prompt clair et direct suffit, sans passer par un processus rigide en plusieurs étapes.
* **Utiliser des skills ciblés et légers** : Si un accompagnement est nécessaire (comme le skill `grill-me` de Matt Pocock), choisir des outils minimalistes (quelques dizaines de lignes) qui posent les bonnes questions (Quoi ? Pour qui ? À quoi ça ressemble ? Comment vérifier ?), plutôt que des manuels de 350 pages.
* **Démarrer une session fraîche** : Commencer une nouvelle conversation (chat) pour chaque nouvelle tâche afin d'éviter le débordement de contexte (*context overflow*).
* **Définir puis itérer** : Réfléchir à ce que l'on veut, le formuler clairement dans un prompt, laisser l'IA exécuter, puis corriger les écarts sur le résultat réel.
