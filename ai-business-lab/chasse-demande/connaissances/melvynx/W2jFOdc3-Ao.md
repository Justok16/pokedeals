1) **Idée principale :** Comment configurer et utiliser correctement **ESLint** dans un projet React avec TypeScript pour automatiser la correction des erreurs, uniformiser le code en équipe et éliminer les mauvaises pratiques de développement.

2) **Outils, sites ou dépôts GitHub cités :**
- *ESLint* (Outil de linting pour JavaScript/TypeScript) : Gratuit. Analyse le code pour détecter et corriger les erreurs de syntaxe, de style et de logique.
- *Prettier* (Outil de formatage) : Gratuit. Souvent couplé à ESLint.
- *PNPM* (Gestionnaire de paquets) : Gratuit. Utilisé pour installer les dépendances (alternative à npm/yarn).
- *VS Code* (Éditeur de code) : Gratuit.
- *Notion* (Application de prise de notes) : Gratuit / payant. Héberge le tutoriel écrit et les étapes de configuration d'ESLint.
- *GitHub* (Plateforme de code) : Gratuit / payant. Mentionné pour le dépôt de configurations ESLint (`eslint-plugin-unicorn`, configurations Airbnb, Facebook, Google, etc.).

3) **Astuces concrètes et réutilisables :**
- Initialiser ESLint dans un projet via la commande de configuration (ex: `pnpm create @eslint/config`) pour définir les règles adaptées (JavaScript/TypeScript, modules ESM, environnement navigateur).
- Configurer des plugins populaires comme `eslint-plugin-unicorn` pour appliquer des bonnes pratiques strictes (ex: interdire les abréviations dans les noms de variables, forcer l'utilisation d'opérateurs ternaires au lieu de `if/else` simples).
- Intégrer l'auto-correction d'ESLint à l'enregistrement dans VS Code pour que le linter corrige automatiquement les erreurs de formatage et de syntaxe à la volée.
