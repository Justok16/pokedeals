# J'ARRÊTE d'utiliser NodeJS pour BUN ? (ou pas...)

Vidéo : https://youtu.be/nRc6nbEU9a0 · durée 10:13 · résumé Gemini (gemini-flash-lite-latest, lot de 5) du 2026-10-18
(connaissances générales, non vérifiées : toute règle fiscale ou chiffre est à contrôler à la source officielle)

1) **Idée principale :** Il ne faut pas se précipiter sur les nouvelles technologies (comme Bun ou des alternatives plus récentes) sous prétexte de la « hype » ; l'expérience, la stabilité et l'écosystème de Node.js en font un choix beaucoup plus sûr et pérenne pour les projets professionnels.
2) **Outils, sites ou dépôts cités :**
- **Bun** (gratuit, runtime JavaScript ultra-rapide et tout-en-un).
- **Deno** (gratuit, runtime JavaScript/TypeScript).
- **Node.js** (gratuit, runtime JavaScript basé sur V8).
- **Vite** (gratuit, bundler/outil de build rapide).
- **Webpack** (gratuit, bundler JavaScript traditionnel).
- **Express / Fastify** (gratuits, frameworks web pour Node.js).
- **Axios / Ky** (gratuits, clients HTTP).
- **Vue.js / Svelte / React** (gratuits, frameworks/bibliothèques front-end).
- **Stack Overflow / ChatGPT** (gratuits, plateformes de recherche et d'aide au développement).
3) **Astuces concrètes et réutilisables :**
- Privilégier les outils stables et largement adoptés (comme React ou Node.js) plutôt que de sauter sur chaque nouvelle techno à la mode pour éviter les bugs et le gaspillage de temps.
- S'informer sur les nouvelles technos sans forcément les intégrer immédiatement dans ses projets en production.
- S'appuyer sur les bases solides du JavaScript (DOM, gestion d'erreurs, asynchronous, etc.) plutôt que de courir après les performances marginales d'un nouvel outil.
4) **Chiffres de revenus :** Non précisé.
