# Ma STACK a définitivement changé : voici les nouveautés !

Vidéo : https://youtu.be/rxuN9gsmQAM · durée 14:21 · résumé Gemini (gemini-flash-lite-latest, lot de 5) du 2026-10-12
(connaissances générales, non vérifiées : toute règle fiscale ou chiffre est à contrôler à la source officielle)

1) **Idée principale :** Le créateur présente une mise à jour majeure de **Better-Auth** (une alternative moderne et open source à Auth.js) pour gérer l'authentification dans les applications TypeScript/Next.js, en expliquant pourquoi cet outil surpasse Auth.js et comment l'intégrer avec gestion des organisations, des rôles, des permissions et des tests automatisés.

2) **Outils, sites et dépôts GitHub cités :**
- **Auth.js** (authjs.dev) : bibliothèque d'authentification pour le web (gratuit / open source).
- **Better-Auth** (better-auth.com) : framework d'authentification complet pour TypeScript (gratuit / open source).
- **GitHub** (github.com) : plateforme de code et intégration CI/CD (gratuit / payant).
- **Vercel** (vercel.com) : plateforme de déploiement (gratuit / payant).
- **Neon** (neon.tech) : service de base de données PostgreSQL serverless (gratuit / payant).
- **Playwright** (playwright.dev) : outil de test end-to-end (gratuit / open source).
- **Vitest** (vitest.dev) : framework de test unitaire (gratuit / open source).

3) **Astuces concrètes et réutilisables :**
- Migrer d'une bibliothèque d'authentification instable ou trop complexe (comme Auth.js en version bêta) vers un outil plus modulaire et typé comme Better-Auth.
- Utiliser des plugins pour gérer des fonctionnalités avancées (gestion des organisations, multi-tenant, double facteur d'authentification).
- Mettre en place des tests unitaires et des tests E2E (avec Playwright) exécutés automatiquement à chaque commit via une CI sur GitHub.
- Isoler la base de données de test en créant une nouvelle branche ou une base dédiée par PR pour éviter les conflits lors des tests automatisés.
