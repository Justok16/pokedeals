# Pourquoi TU DOIS utiliser Prettier ?

Vidéo : https://youtu.be/yZgABMcPvYk · durée 5:30 · résumé Gemini (gemini-flash-lite-latest, lot de 10) du 2026-10-19
(connaissances générales, non vérifiées : toute règle fiscale ou chiffre est à contrôler à la source officielle)

1) **Idée principale :** Explication de la différence fondamentale entre une **librairie** et un **framework** (en prenant l'exemple de React vs Vue.js/Next.js), tout en démontrant pourquoi **Prettier** est un outil indispensable pour formater le code automatiquement et gagner du temps.

2) **Outils, sites ou dépôts GitHub cités :**
- *Prettier* (Outil de formatage de code) : Gratuit. Formate automatiquement le code selon des règles prédéfinies.
- *VS Code* (Éditeur de code) : Gratuit. Utilisé avec Prettier et ESLint.
- *ESLint* (Outil d'analyse de code / linter) : Gratuit. Détecte les erreurs et problèmes de style.
- *React* (Librairie JavaScript) : Gratuit. Présenté comme une librairie (pas de structure imposée, pas d'outils par défaut pour le routage ou le state management).
- *Vue.js* (Framework JavaScript) : Gratuit. Présenté comme un framework progressif avec des outils intégrés (routing, state management, etc.).
- *Angular* (Framework JavaScript) : Gratuit. Framework complet.
- *Remix* (Framework React) : Gratuit. Framework.
- *Axios* (Librairie JavaScript) : Gratuit. Librairie de requêtes HTTP.
- *Next.js* (Framework React) : Gratuit. Framework basé sur React.
- *Notion* (Application de prise de notes) : Gratuit / payant. Utilisé pour héberger la mindmap du cours.

3) **Astuces concrètes et réutilisables :**
- Intégrer **Prettier** dans son workflow pour formater le code automatiquement à chaque sauvegarde et éviter de perdre du temps sur l'indentation et la ponctuation.
- Comprendre la distinction conceptuelle : une *librairie* est appelée par votre code pour effectuer une tâche spécifique (tu utilises une librairie), tandis qu'un *framework* fournit la structure globale et appelle votre code (le framework t'utilise / définit le squelette).
- Choisir des outils adaptés à ses besoins (librairies) lorsqu'on utilise une technologie flexible comme React, plutôt que de s'enfermer dans un framework rigide si ce n'est pas nécessaire.
