# Les Tests ne sont pas Optionnels, voici Pourquoi !

Vidéo : https://youtu.be/rsRihrFoqtc · durée 8:45 · résumé Gemini (gemini-flash-lite-latest, lot de 8) du 2026-10-19
(connaissances générales, non vérifiées : toute règle fiscale ou chiffre est à contrôler à la source officielle)

1. L'idée principale de cette vidéo est de démontrer pourquoi il est essentiel et obligatoire de tester ses applications, en particulier les applications React, pour éviter de casser le code lors de l'évolution des projets (apparition de nouveaux fichiers ou modification de codes existants).

2. Outils, sites ou dépôts GitHub cités :
- Aucun nom exact d'outil, de site ou de dépôt GitHub n'est explicitement mentionné dans cette vidéo. Le créateur utilise simplement des schémas dessinés sur écran et montre du code React/TypeScript sans nommer de librairie de test spécifique (ni payante, ni gratuite).

3. Astuces concrètes et réutilisables :
- Utiliser le mode "code coverage" pour vérifier que chaque ligne de code, de composant, d'événement et de fonction est bien lue et testée.
- Concevoir des composants avec des tests unitaires et de fonctions, surtout en entreprise où les modifications impactent de nombreux fichiers interdépendants.
- S'appuyer sur une CI (Continuous Integration) qui valide automatiquement les tests à chaque *pull request* avant de pousser en production.
